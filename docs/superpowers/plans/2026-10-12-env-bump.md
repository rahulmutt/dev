# Env Bump and Config Validation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the daily mise bump into an environment bump that also refreshes Codex hook trust, and add a validator, run against the built image on every PR, that checks the Claude, Codex and pi dotfiles.

**Architecture:** `scripts/env-bump.sh` (renamed from `mise-bump.sh`) changes only two files: `.config/mise/config.toml` and the `[hooks.state]` tables of `.codex/config.toml`. Every piece that runs offline sits behind a pure flag so it can be unit-tested. `scripts/validate-config.sh` is a separate, read-only checker. `validate-devpod.sh` runs it inside the image with `docker run`, so DevPod CI on every PR exercises it at exactly the shipped versions.

**Tech Stack:** bash, awk, jq, mise, GitHub Actions; the `claude`, `codex` and `pi` CLIs inside the image.

**Spec:** `docs/superpowers/specs/2026-10-12-env-bump-design.md`

## Global Constraints

- All shell scripts: `#!/usr/bin/env bash`, pass `mise run lint` (shellcheck over `base/*.sh scripts/*.sh scripts/tests/*.sh`).
- Tests are offline (no network, no real `claude`/`codex`/`mise`), use the repo's tiny `ok`/`bad` assertion style, and run under `mise run test`.
- A failed env-bump run leaves `.config/mise/config.toml` **and** `.codex/config.toml` exactly as they were and opens no PR.
- A bumped tool rejecting a setting does **not** fail env-bump; it surfaces as a failing `validate-config.sh` in the PR's DevPod checks.
- No check may need Claude or Codex credentials.
- `MISE_BUMP_TOKEN` keeps its name. Workflow name `Env Bump`, concurrency group and branch `env-bump`, commit/title `chore(env): bump toolchain and refresh codex hook trust`.
- Skipped-by-name Claude marketplaces: exactly `always-further`. Official marketplace repo: `anthropics/claude-plugins-official`.
- A settings file must not contain `mise/installs/<tool>/<digit>…`; paths through `latest/` pass.

## Review Focus

- **Rewriting the real `.codex/config.toml` with an unchanged hook set produces a byte-identical file.** Otherwise every daily run opens a whitespace-only PR. Pinned in Task 2 (round-trip test on the real config).
- **Hook summary when the *before* config has no hooks tables.** A naive `NR==FNR` awk treats the after-file as the before-file and reports nothing. Expected: every hook listed as added. Pinned in Task 2.
- **A non-hook table after the hooks tables** (say a `[plugins…]` table someone appends later) survives a rewrite in place. Pinned in Task 2.
- **A major-version symlink path such as `installs/node/26/bin/node` counts as versioned.** It drifts on a major bump, so it fails, and only `latest/` passes. Pinned in Task 4.
- **`codex doctor --json` without a `config.load` check, or with unparseable output, fails the check.** It must not pass silently. Pinned in Task 6.

```bash
# Print <config> with every [hooks.state."…"] table removed and trailing blank
# lines trimmed, then -- if <block> is non-empty -- a blank line and <block>.
# Pure over the two files.
rewrite_hooks() {
    awk '
        /^\[hooks\.state\./ { skip = 1; next }
        /^\[/ { skip = 0 }
        skip { next }
        { lines[++n] = $0 }
        END {
            while (n > 0 && lines[n] == "") n--
            for (i = 1; i <= n; i++) print lines[i]
        }
    ' "$1"
    if [ -s "$2" ]; then
        echo
        cat "$2"
    fi
}

# Emit "<hook key><TAB><trusted hash>" for every [hooks.state] table.
hook_pins() {
    awk '
        /^\[hooks\.state\."/ {
            key = $0
            sub(/^\[hooks\.state\."/, "", key)
            sub(/"\][[:space:]]*$/, "", key)
            next
        }
        /^\[/ { key = "" }
        key != "" && /^trusted_hash[[:space:]]*=/ {
            hash = $0
            sub(/^[^"]*"/, "", hash)
            sub(/".*$/, "", hash)
            print key "\t" hash
            key = ""
        }
    ' "$1"
}

# Markdown list of hooks added, changed or removed between two configs, or
# nothing when the trusted set is unchanged. FILENAME == ARGV[1] rather than
# NR == FNR, so an empty before-config is not mistaken for the after-config.
render_hooks_summary() {
    local rows
    rows="$(awk -F'\t' '
        FILENAME == ARGV[1] { before[$1] = $2; next }
        { after[$1] = $2 }
        END {
            for (k in after) {
                if (!(k in before)) print "added\t" k
                else if (before[k] != after[k]) print "changed\t" k
            }
            for (k in before) if (!(k in after)) print "removed\t" k
        }
    ' <(hook_pins "$1") <(hook_pins "$2") |
        sort -t"$TAB" -k2,2 |
        awk -F'\t' '{ printf "- %s `%s`\n", $1, $2 }')"

    [ -n "$rows" ] || return 0

    echo "### Codex hook trust"
    echo
    echo "Re-trusted with \`scripts/codex-hook-hashes.sh\` after installing the plugins declared in \`$CODEX_CONFIG\`:"
    echo
    echo "$rows"
}
```

- [ ] **Step 1: Add `refresh_codex_hooks`**

Above `bump()`:

```bash
# Write the current [hooks.state] block for the plugins in $CODEX_CONFIG to
# <block>. Installs the plugins into a scratch CODEX_HOME, so neither the
# runner's codex state nor this repo's config is touched. codex comes from
# the toolchain pins: the workflow runs mise-action with install: false, so it
# is only present if the mise bump just moved it -- hence the explicit install.
# Run from the scratch home so codex doesn't also load this repo's
# .codex/config.toml as project config.
refresh_codex_hooks() {
    local block="$1" codex_home codex_bin status=0

    codex_home="$(mktemp -d)"
    cp "$CODEX_CONFIG" "$codex_home/config.toml"

    if mise install codex && codex_bin="$(mise which codex)"; then
        (
            cd "$codex_home"
            export CODEX_HOME="$codex_home"
            PATH="$(dirname "$codex_bin"):$PATH"
            bash "$SCRIPT_DIR/install-codex-plugins.sh" >&2 &&
                bash "$SCRIPT_DIR/codex-hook-hashes.sh" >"$block"
        ) || status=$?
    else
        status=1
    fi

    rm -rf "$codex_home"
    return "$status"
}
```

- [ ] **Step 2: Wire it into `bump()`**

Replace `bump()` with:

```bash
bump() {
    local summary_out="$1" before codex_before stderr_log block summary hooks

    cd "$REPO_ROOT"

    before="$(mktemp)"
    codex_before="$(mktemp)"
    stderr_log="$(mktemp)"
    block="$(mktemp)"
    # shellcheck disable=SC2064  # expand now: the vars are gone by trap time otherwise
    trap "rm -f '$before' '$codex_before' '$stderr_log' '$block'" EXIT
    cp "$CONFIG" "$before"
    cp "$CODEX_CONFIG" "$codex_before"

    # A failed run must leave no changes behind, in either file.
    restore() {
        cp "$before" "$CONFIG"
        cp "$codex_before" "$CODEX_CONFIG"
    }

    # A fresh CI runner has never trusted this config, and mise treats an
    # untrusted config as a hard error, not a silent skip.
    mise trust --yes "$CONFIG"

    # Capture mise's stderr to a file so tool_resolution_failed can inspect it
    # afterward, but also copy it to this job's own stderr (after the run
    # completes, so the copy is not racing mise's writes) so an operator
    # watching the Actions log still sees everything mise printed. Both passes
    # append to the same log so the partial-bump check covers the whole bump.
    : >"$stderr_log"
    if ! mise upgrade --bump --yes --minimum-release-age 0s "${DEPENDENCY_TOOLS[@]}" 2>>"$stderr_log" ||
        ! mise upgrade --bump --yes --minimum-release-age 0s 2>>"$stderr_log"; then
        cat "$stderr_log" >&2
        echo "env-bump: mise upgrade exited nonzero" >&2
        restore
        exit 1
    fi
    cat "$stderr_log" >&2

    # A partial bump (one tool failed to resolve, the rest silently moved on)
    # must fail loudly rather than open a PR that looks like a clean bump.
    # No summary is written below, so no PR is opened; this is meant to be a
    # noisy daily failure until a human removes or fixes the dead tool.
    if tool_resolution_failed "$stderr_log"; then
        echo "env-bump: mise failed to resolve one or more pinned tools (see stderr above)." >&2
        echo "env-bump: refusing to open a PR for a partial bump." >&2
        restore
        exit 1
    fi

    # Re-trust the codex plugin hooks. Runs every day, not only when codex
    # moved: plugins are installed from their marketplaces' default branches,
    # so a hook can change upstream with no pin moving. Without the plugins
    # installed there is no way to compute correct hashes, and stale ones
    # would mislead, so a failure here also refuses the PR.
    if ! refresh_codex_hooks "$block"; then
        echo "env-bump: refreshing codex hook trust failed (see above)." >&2
        restore
        exit 1
    fi
    rewrite_hooks "$codex_before" "$block" >"$CODEX_CONFIG"

    summary="$(render_summary "$before" "$CONFIG")"
    hooks="$(render_hooks_summary "$codex_before" "$CODEX_CONFIG")"
    if [ -n "$hooks" ]; then
        summary="$summary"$'\n\n'"$hooks"
    fi
    printf '%s\n' "$summary"
    if [ -n "$summary_out" ]; then
        printf '%s\n' "$summary" > "$summary_out"
    fi
}
```

#!/usr/bin/env bash
#
# validate-config.sh — check the home dotfiles against the installed tools.
#
# Validates ~/.claude/settings.json, ~/.codex/config.toml and
# ~/.pi/agent/settings.json: no versioned mise install paths, each tool
# accepts its settings, and every declared plugin and package resolves.
# Read-only: plugin installs happen in scratch HOMEs.
#
# Every check runs even if an earlier one failed, so one run reports
# everything. Exits 1 if any check failed. Needs no Claude or Codex login, but
# does need the network (plugin installs clone their marketplaces).
#
# Usage:
#   scripts/validate-config.sh
#
# Run in the built image by scripts/validate-devpod.sh.

set -uo pipefail  # no -e: a failing check must not stop the others

SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)"
CODEX_HOOK_HASHES="${CODEX_HOOK_HASHES:-$SCRIPT_DIR/codex-hook-hashes.sh}"

CLAUDE_SETTINGS="$HOME/.claude/settings.json"
CODEX_CONFIG="${CODEX_HOME:-$HOME/.codex}/config.toml"
PI_SETTINGS="$HOME/.pi/agent/settings.json"

SCRATCH="$(mktemp -d)"
trap 'rm -rf "$SCRATCH"' EXIT

failures=0
pass() { echo "  ok    $*"; }
fail() { echo "  FAIL  $*"; failures=$((failures + 1)); }
skip() { echo "  skip  $*"; }
detail() { sed 's/^/          /'; }

# need <file>: fail and return 1 if it doesn't exist.
need() {
    [ -f "$1" ] && return 0
    fail "$1 is missing"
    return 1
}

# A settings file must not name a versioned mise install path: it breaks the
# moment the tool is bumped. Point at installs/<tool>/latest/ instead, which
# mise keeps as a symlink to the installed version. Major/minor symlinks
# (installs/node/26) still drift on a major bump, so they count as versioned.
check_pinned_paths() {
    local f hits
    for f in "$CLAUDE_SETTINGS" "$CODEX_CONFIG" "$PI_SETTINGS"; do
        need "$f" || continue
        hits="$(grep -noE 'mise/installs/[^/"]+/[0-9][^/" ]*' "$f" || true)"
        if [ -n "$hits" ]; then
            fail "$(basename "$f") names a versioned mise install path; use installs/<tool>/latest/"
            printf '%s\n' "$hits" | detail
        else
            pass "$(basename "$f"): no versioned mise install paths"
        fi
    done
}

# pi has no validator of its own (`pi list` exits 0 on invalid JSON), so check
# the shape this repo relies on: an object whose packages are strings.
check_pi_settings() {
    need "$PI_SETTINGS" || return
    if jq -e 'type == "object" and ((.packages // []) | type == "array" and all(type == "string"))' \
        "$PI_SETTINGS" >/dev/null 2>&1; then
        pass "pi settings.json"
    else
        fail "pi settings.json is not an object with a string-array packages list"
    fi
}

# Each declared package's install dir exists. A pinned source ends in
# @<version> or @<ref>; the install dir doesn't.
check_pi_packages() {
    local src pkg repo dir
    need "$PI_SETTINGS" || return
    for src in $(jq -r '.packages // [] | .[] | strings' "$PI_SETTINGS" 2>/dev/null); do
        case "$src" in
            npm:@*@*|npm:[!@]*@*) pkg="${src#npm:}"; dir="$HOME/.pi/agent/npm/node_modules/${pkg%@*}" ;;
            npm:*) dir="$HOME/.pi/agent/npm/node_modules/${src#npm:}" ;;
            git:*@*) repo="${src#git:}"; dir="$HOME/.pi/agent/git/${repo%@*}" ;;
            git:*) dir="$HOME/.pi/agent/git/${src#git:}" ;;
            *) fail "pi package $src has an unchecked source type"; continue ;;
        esac
        if [ -d "$dir" ]; then
            pass "pi package $src installed"
        else
            fail "pi package $src not installed at $dir"
        fi
    done
}

main() {
    echo "==> pinned paths"
    check_pinned_paths
    echo "==> pi"
    check_pi_settings
    check_pi_packages

    if [ "$failures" -gt 0 ]; then
        echo "${failures} check(s) failed"
        exit 1
    fi
    echo "config OK"
}

main "$@"

# claude_doctor <home>: print `claude doctor` output for that HOME. Run from a
# scratch dir so no project settings are mixed in. It exits 0 even when it
# finds invalid settings, so callers match its output.
claude_doctor() {
    local dir
    dir="$(mktemp -d -p "$SCRATCH")"
    (cd "$dir" && HOME="$1" claude doctor </dev/null 2>&1) || true
}

# Claude validates settings against its own schema, for the version installed.
# The canary guards the output match: if a claude bump rewords "Invalid
# settings", the canary stops matching and this fails instead of passing
# forever.
check_claude_settings() {
    local canary out
    need "$CLAUDE_SETTINGS" || return

    canary="$SCRATCH/claude-canary"
    mkdir -p "$canary/.claude"
    echo '{"permissions": {"defaultMode": "notAMode"}}' >"$canary/.claude/settings.json"
    if ! claude_doctor "$canary" | grep -qF 'Invalid settings'; then
        fail "claude doctor did not report a known-invalid settings file (detection broken)"
        return
    fi

    out="$(claude_doctor "$HOME")"
    if printf '%s\n' "$out" | grep -qF 'Invalid settings'; then
        fail "claude rejects settings.json"
        printf '%s\n' "$out" | sed -n '/Invalid settings/,/^$/p' | detail
    else
        pass "claude accepts settings.json"
    fi
}

# Every enabled plugin installs, in a scratch HOME holding a copy of the
# settings, so the real ~/.claude is never touched.
check_claude_plugins() {
    local home out repo id market declared
    need "$CLAUDE_SETTINGS" || return

    home="$SCRATCH/claude-plugins"
    mkdir -p "$home/.claude"
    cp "$CLAUDE_SETTINGS" "$home/.claude/settings.json"

    for repo in "$OFFICIAL_MARKETPLACE_REPO" $(jq -r '.extraKnownMarketplaces // {} | .[] | .source | select(.source == "github") | .repo' "$CLAUDE_SETTINGS"); do
        if out="$(cd "$home" && HOME="$home" claude plugin marketplace add "$repo" </dev/null 2>&1)"; then
            pass "claude marketplace $repo"
        else
            fail "claude marketplace $repo"
            printf '%s\n' "$out" | detail
        fi
    done

    declared="$(jq -r '.extraKnownMarketplaces // {} | keys[]' "$CLAUDE_SETTINGS"; echo "$OFFICIAL_MARKETPLACE")"
    for id in $(jq -r '.enabledPlugins // {} | to_entries[] | select(.value == true) | .key' "$CLAUDE_SETTINGS"); do

        if printf '%s\n' "${EXTERNAL_MARKETPLACES[@]}" | grep -qxF "$market"; then

            continue
        fi
        if ! printf '%s\n' "$declared" | grep -qxF "$market"; then
            fail "claude plugin $id: marketplace $market is not declared in extraKnownMarketplaces"

        if out="$(cd "$home" && HOME="$home" claude plugin install "$id" </dev/null 2>&1)"; then

        else
            fail "claude plugin $id"
            printf '%s\n' "$out" | detail
        fi
    done
}

# Codex validates config.toml as it loads it; `codex doctor --json` reports
# that as checks["config.load"], with unrecognized keys as a warning. Its exit
# status is 1 without a login, so only the report is used. A missing check or
# unparseable report fails rather than passing silently.
check_codex_config() {
    local report status
    need "$CODEX_CONFIG" || return
    report="$(cd "$SCRATCH" && codex doctor --json </dev/null 2>/dev/null)"
    status="$(jq -r '.checks["config.load"].status // "missing"' <<<"$report" 2>/dev/null)" || status=unparseable
    if [ "$status" = ok ]; then
        pass "codex accepts config.toml"
    else
        fail "codex config.load is $status"
        jq -r '.checks["config.load"] // {} | .summary // empty, (.. | strings | select(test("unrecognized|ignored")))' \
            <<<"$report" 2>/dev/null | sort -u | detail
    fi
}

# Print each [plugins."<id>"] in $CODEX_CONFIG with enabled = true.
codex_enabled_plugins() {
    awk '
        /^\[/ { id = "" }
        /^\[plugins\."[^"]+"\]/ {
            id = $0
            sub(/^\[plugins\."/, "", id)
            sub(/"\].*$/, "", id)
        }
        id != "" && /^enabled[ \t]*=[ \t]*true/ { print id }
    ' "$CODEX_CONFIG"
}

check_codex_plugins() {
    local list id
    need "$CODEX_CONFIG" || return
    list="$(cd "$SCRATCH" && codex plugin list 2>&1 || true)"
    for id in $(codex_enabled_plugins); do
        if printf '%s\n' "$list" | grep -E "^$id +installed, enabled" >/dev/null; then
            pass "codex plugin $id installed"
        else
            fail "codex plugin $id not installed, enabled"
        fi
    done
}

# Pinned trust hashes go stale when a plugin changes a hook; codex then
# silently stops running it. env-bump refreshes them daily.
check_codex_hooks() {
    local out
    need "$CODEX_CONFIG" || return
    if out="$(cd "$SCRATCH" && bash "$CODEX_HOOK_HASHES" --check 2>&1)"; then
        pass "codex hook trust ($out)"
    else
        fail "codex hook trust"
        printf '%s\n' "$out" | detail
    fi
}
